sample product with `h5py` and enumerates its HDF5 tree and metadata **without reading full
image cubes** (two of these files are 14–26 GB, so only shapes/dtypes are read for large
datasets; scalar/small metadata is read in full). Raw script output is not committed (see
`docs/data_access.md`); this table is the durable summary.

`identification/boundingPolygon` (lon/lat/height triplets, WGS84) and, for geocoded L2
products, the `projection` (EPSG) code and `xCoordinates`/`yCoordinates` grid extents — not
assumed in advance.

## Product structure notes

### RSLC (Files 1, 2) — `science/LSAR/RSLC/...`
- Complex SLC image cubes: `swaths/frequencyA/{HH,HV}` (54720 × 26704, complex64, ~10.9 GB
  each) and `swaths/frequencyB/{HH,HV}` (54720 × 6676, complex64, ~2.7 GB each). Frequency A
  has finer range spacing (~9.5 m ground-range on File 1) than Frequency B (~38 m).
  Slant-range and per-line `zeroDopplerTime` axes are provided.
  **Note:** File 1 is dual-polarization Freq A/B (`isMixedMode: True`); File 2's `frequencyB`
  is also present with HH/HV. Both are radar-coordinates (`isGeocoded: False`), so geolocation
  is via the `metadata/geolocationGrid` cube (`coordinateX`/`coordinateY`, `epsg=4326`,
  `incidenceAngle`, `heightAboveEllipsoid`, etc.) rather than direct x/y axes.
- `identification` group carries track/frame/orbit direction, `boundingPolygon`,
  `zeroDopplerStartTime`/`EndTime`, `lookDirection` (Left for both), `radarBand`,
  `productSpecificationVersion`, `compositeReleaseId`.
- `metadata/RFI`, `metadata/calibrationInformation`, `metadata/orbit`,
  `metadata/processingInformation` groups hold calibration/RFI/orbit ancillary data (all small).

### GCOV — L-band (File 3) — `science/LSAR/GCOV/grids/...`
- Geocoded covariance grids: `frequencyA/{HHHH,HVHV}` (34128 × 34704, float32, ~4.4 GB each)
  and `frequencyB/{HHHH,HVHV}` (4266 × 4338, float32). Only the **diagonal** terms HHHH and
  HVHV are present (`listOfCovarianceTerms = ['HHHH','HVHV']`) — no off-diagonal (e.g. HHHV)
  terms in this dual-pol product.
- `xCoordinates`/`yCoordinates` (UTM 46N meters) + `projection` (EPSG 32646) give a direct
  geocoded grid — no separate lat/lon cube needed.
- `staticLayersDataAccess` attribute points to a companion static-layers product (not present
  locally).

### GCOV — S-band (File 5) — `science/SSAR/GCOV/grids/...`
- Note the top-level group is `science/SSAR/...` (S-band), not `science/LSAR/...` — a real
  structural difference module code must account for (see `nisar_tools/io.py`).
- Geocoded covariance grid: `frequencyA/{HHHH,HVHV,HHHV}` (33192 × 34272). This product
  **does** include the off-diagonal `HHHV` term (complex64) in addition to the two diagonal
  terms (float32) — richer polarimetric content than the L-band GCOV sample (File 3), which
  only has the two diagonal terms.
- Single frequency (A only); `radarBand = S`; processed by ISRO (`processingCenter: ISRO`)
  under baseline P00500, vs. JPL/P05023 for the L-band products.

### GUNW (File 4) — `science/LSAR/GUNW/grids/frequencyA/...`
- `unwrappedInterferogram/HH/`: `unwrappedPhase`, `coherenceMagnitude`, `connectedComponents`,
  `ionospherePhaseScreen` (4248 × 4320, the "full-res" unwrapped/geocoded grid).
- `wrappedInterferogram/HH/`: `wrappedInterferogram` (complex64) and `coherenceMagnitude`,
  at 4x the resolution (16992 × 17280) — the multilooked wrapped interferogram before
  unwrapping.
- `pixelOffsets/HH/` group also present (offset-tracking layers).
- Single polarization (HH only); geocoded to EPSG:32643 (UTM 43N), consistent with the
  034/073 Punjab-region footprint shared with Files 1 and 2.
- `identification` group explicitly records `referenceZeroDopplerStartTime`/`EndTime` and
  `secondaryZeroDopplerStartTime`/`EndTime`, which match Files 1 and 2 respectively —
  this is the definitive confirmation of the stated File 1 + File 2 → File 4 relationship.

## Implications for module design

- **Module 01 (RSLC fundamentals, File 1)**: use `swaths/frequencyA/HH` (10.9 GB complex64) —
  must read small spatial windows/slices, never the full array, given file size.
- **Module 02 (repeat-pass change detection, Files 1 & 2)**: both are radar-coordinate (not
  geocoded) SLCs from the same track/frame, 12 days apart — genuinely co-registrable without
  reprojection gymnastics, good for a backscatter-differencing demo.
- **Module 03 (GCOV polarimetric analysis, File 3)**: only HHHH/HVHV diagonal terms available
  — an HH/HV ratio and simple thresholding are demonstrable; no true polarimetric
  decomposition (needs off-diagonal/full covariance) is possible with this specific file.
- **Module 04 (InSAR basics, File 4)**: unwrapped phase, coherence, connected components, and
  ionosphere screen are all present — sufficient for a full read → mask-by-coherence →
  visualize-displacement walkthrough.
- **Module 05 (L vs S band, Files 3 & 5)**: same geographic footprint, both geocoded to (near)
  matching UTM zones, both have HHHH/HVHV — a direct, defensible band comparison.
- **Module 06 (S-band GCOV standalone, File 5)**: the `science/SSAR/...` path prefix and the
  presence of the off-diagonal `HHHV` term are the two structural points worth calling out
  relative to the L-band GCOV file.
